# A股产业链映射、Candidate验证与成熟度

## 目的

在Market Theme和Driver已经形成后，回答：

> A股哪一段真实受益，谁最直接，谁已经兑现，谁只是主题联想。

A股验证不能反向改写昨夜Theme Rank；它只决定这个Theme能映射出哪些合格公司，以及这些公司能否进入Core/Watch。

## Theme → A股经济链

每个重要Theme先拆经济传导，再找股票：

```text
Market Theme / Driver
→ 核心产品/技术/靶点/平台
→ 需求/价格/供给变化
→ 直接受益环节
→ 核心上游/下游
→ 设备/材料/设计/制造/模组/分销等适用环节
→ A股 Candidate
```

不设置固定Candidate数量。真实相关公司少就少；相关环节多则充分展开；禁止只挑一只“代表股”代替完整经济链，也禁止为凑数量加入弱映射。

价格型Driver必须双向分析。例如DRAM/NAND涨价，对模组/分销同时检查：售价与库存收益、采购成本、营运资金和终端需求压力。

## Economic Chain Coverage Gate + Omission Challenge

在进入Preliminary Validation前，对每个Top Theme做**经济链覆盖 + 遗漏反查**。目标不是增加股票数量，而是避免两种假闭环：

1. 找到几只显眼公司后提前停止；
2. 模型自己少列了关键节点，却因为“已列节点全部有状态”就宣布覆盖完成。

### 第一步：初始节点表

按Driver实际机制识别经济上不同的节点，例如（仅在适用时）：

- 直接产品/核心器件；
- 关键接口、控制器、配套芯片或稀缺材料；
- 模组/系统集成/制造；
- 扩产必需的设备、检测、工艺材料；
- 价格/缺货型Driver下的库存、分销或渠道环节；
- 可能被替代、成本受损或方向相反的关键环节。

每个**重要且经济机制不同**的节点必须得到一个状态：

- `covered`：已找到至少一个合理A股Candidate；
- `no-valid-A-share`：已查找但没有满足基础相关性的A股公司；
- `not-applicable`：该节点不适用于当前Driver；
- `needs-check`：信息不足，必须披露，不能假装已覆盖。

### 第二步：Omission Challenge

**不能在这里直接宣布PASS。** 必须抛开初始节点表，至少用两条独立视角重新推导一次：

**A. Physical / Technical Dependency**

从最终需求或产品架构反推：Driver要真正兑现，哪些东西是“必须跟着增加/升级/被验证”的？检查核心部件、接口/控制器、配套芯片、材料、制造、测试、设备等必需依赖。

对于服务器、半导体、光通信、先进封装等复杂技术系统，**这一步至少引用一份能描述产品架构/BOM/标准接口/工艺流程的可靠技术来源**（公司技术资料、标准组织、权威产业技术资料等），不能只凭模型记忆宣布完整。找不到足够资料时，`Omission Challenge=needs-check`。

**B. Economic Value / Capex Flow**

从经济价值反推：谁因销量、ASP、份额、库存、毛利、订单或资本开支真正获得价值？谁反而承担采购成本、营运资金、替代或需求受损？

将A/B两次反推结果与初始节点表比较：

- 出现新的重要经济节点 → 补入节点表、搜索A股Candidate并给状态；
- 某节点只是同质公司扩展、L3/L4弱联想 → 不必为数量继续扩；
- 两种反推都没有产生新的重要节点 → 才允许Coverage Gate通过。

**Coverage Gate的退出条件是“节点集合本身经过独立反查仍然完整”，不是“自己列出的节点都打了勾”。** 找到2–5只熟悉龙头当然也不是退出条件。

输出时不必展示推理过程；对Top Theme至少用一行`Economic Chain Coverage`说明主要节点，并明确`Omission Challenge: passed / needs-check`。若`needs-check`涉及可能改变Candidate集合的关键节点，不能把该Theme标成“候选已充分展开”。

## 映射层级 L1–L4

- L1：直接生产对应产品，或拥有真正可比的靶点/平台/管线。
- L2：核心上游/下游，Driver持续会明确改变其需求或盈利。
- L3：间接受益，弹性有限或传导链较长。
- L4：只有技术名词、规划、研发项目或市场联想。

L4不得进Core。

## Candidate → Preliminary Validation → Shortlist

对每个Theme分别完成初筛，不能先把不同Theme股票混成总榜。Preliminary Validation只能在Economic Chain Coverage Gate之后开始；Candidate阶段先高召回，淘汰在这里发生。

Preliminary Validation检查：

1. 产品/管线是否匹配；
2. 产业位置和传导方向是否正确；
3. 是否有基本公司、监管、客户、技术或产业证据；
4. 是否存在一眼可推翻的反证；
5. 是否值得完整深挖。

快速淘汰名字相似、业务不符、位置错误、明显蹭概念者。

进入Shortlist至少满足一项：L1/L2、较高业绩/管线弹性、真实0→1、稀缺/龙头位置、明显A股定价错位线索、同行PK后有优势。

## Shortlist 10步Deep Validation

严格按以下证据顺序：

1. 公司官方披露
2. 交易所和监管资料
3. 订单与客户验证
4. 技术与资质验证
5. 产业景气数据
6. 财务和经营交叉验证
7. 同行横向对比
8. 反证与风险检查
9. 研究和媒体
10. 市场讨论

先硬证据、再交叉验证、最后看观点。市场讨论只作线索。

## 商业化公司 E1–E5

只描述业务兑现阶段：

- E1：已有显著收入、利润或订单。
- E2：订单、产能或收入快速增长。
- E3：客户验证、小批量或量产节点临近。
- E4：有真实业务基础，尚无明确订单或规模兑现。
- E5：纯概念或未证实。

## Biotech P1–P5

只描述管线成熟度：

- P1：监管批准或已商业化。
- P2：注册阶段、III期关键成功，或NDA/BLA已提交/受理/关键审评。
- P3：III期进行中、II期较强PoC或进入明确关键性临床。
- P4：IND获批、I期/I-II期、初步人体数据。
- P5：临床前、尚未人体临床或仅早期平台。

**锁死语义：商业化产业只用E；Biotech只用P；技术/价格位置只用T_static。不得出现“光模块P3回撤”“药物E1临床III期”这类混用。**

## Evidence

Evidence只回答“A股映射/业务/管线关系有多强的证据支持”：

- High：公司、监管、客户/订单、临床注册或权威技术证据充分；
- Medium：多个独立来源形成相互印证；
- Low：单一间接线索或证据链不完整；
- Unknown：无法验证。

业务真实不等于本次海外Driver与公司的映射Evidence自动为High。

## 必答项

商业产业至少回答：

- 具体产品/材料/设备/器件/客户环节是什么；
- 是收入、订单、客户验证、小批量、研发还是概念；
- 客户/供应链关系和收入占比能否验证；
- Driver对收入、利润、成本、库存或资本开支的方向是什么。

Biotech至少回答：

- 靶点、平台、适应症、管线、临床阶段、监管节点、权利归属；
- 海外结果与A股是否同靶点/同路线/同适应症且可比；
- 竞争药物和失败数据是否构成反证。

## 同行PK、反证与推翻条件

每个Theme内部横向比较：映射直接度、产品纯度、收入占比、毛利率/盈利弹性、订单、客户、产能、技术壁垒、龙头地位和估值。

主动检查：产品是否一致、量产/客户/收入是否缺失、海外路线是否替代本公司、利好是否只留在海外、原料涨价是否压缩下游利润、竞争路线是否更强。

每个进入Core/高优先Watch的候选都给可操作的推翻条件。
